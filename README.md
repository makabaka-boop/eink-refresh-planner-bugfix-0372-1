# 离线电子纸刷新规划

完全离线（无网络、无第三方依赖、无构建步骤）的单页工具：在 48×48 黑白像素、
3×3 个**固定瓦片**（每瓦 16×16）上编辑至多 20 帧目标画面，由 Web Worker 在
**整段帧序列**上求总费用最小的合法刷新方案，逐帧展示画面、瓦片残影计数与费用，
播放与导出共用同一份求解结果。

## 规则模型

- 初始屏显为全白、各瓦片残影计数均为 0；任一瓦片计数 **不得超过 2**。
- 每帧必须准确显示目标画面，二选一：
  - **全刷 F**：费用 **600**，全部瓦片残影计数清零。
  - **局刷 P**：对所有本帧发生变化的瓦片分别局刷，费用
    `Σ_变化瓦片 (30 + 该瓦片改变的像素数)`（无变化瓦片费用 0），
    每个发生变化的瓦片计数 **+1**；未变化瓦片计数不变。
    若任一变化瓦片计数已为 2，则该帧局刷非法，必须选全刷。

## 求解算法（不是逐帧贪心）

在整个帧序列上做动态规划：状态为 9 个瓦片残影计数构成的向量
（每位 0/1/2，三进制编码，最多 3⁹=19683 个状态）；每帧两条转移边
F 与 P，取跨所有末状态的最小键值。比较键按题目要求的顺序：

1. 总费用最小；
2. 全刷次数较少；
3. 动作序列逐帧比较，“全刷先于局刷”（F 编码 0、P 编码 1，帧 0 占最高位）。

F 恒合法，故任意帧序列至少存在一个合法方案。20 帧规模下实测耗时约 10ms。

## 文件

| 路径 | 说明 |
| --- | --- |
| `index.html` | 离线页面：像素编辑器、帧管理、Blob Worker 求解、逐帧结果表、播放器、JSON 导入/导出 |
| `js/planner-core.js` | 纯逻辑核心（UMD，无 DOM 依赖）：转移计算、DP、全枚举对拍器、Worker 源码生成、过期请求管理 supervisor |
| `test/planner.test.js` | Node 内置 test runner：小瓦片数枚举全部 2^N 动作序列与 DP 对拍、规则/裁决定值用例、旧 Worker 结果迟到（vm 执行真实 Worker 源码） |
| `test/dom-smoke.js` | 精简 DOM 桩下端到端冒烟：编辑 → 求解 → 结果表 → 播放 → 导出/导入 |

## 使用

直接用浏览器打开 `index.html`（或任意静态服务器，如 `npx serve .`）。
Worker 由 `Blob URL` 内联创建，不请求任何网络资源；不支持 Worker 的环境
自动回退到主线程同步执行同一份求解代码。

操作流程：

1. 在左侧 48×48 画布上用画笔/橡皮编辑当前帧（红线为 3×3 瓦片边界），
   可复制/新增/删除帧（≤20）；
2. 点击 **Worker 整段求解**；修改帧后旧结果标记为过期、导出锁定，需重新求解；
3. 右侧逐帧表展示目标缩略图、动作、本帧/累计费用、变化瓦片（改变像素数）、
   动作前后的 9 瓦片计数；点行可跳转播放位置；
4. 播放器逐步/自动演示屏显与计数；**导出 JSON**（含帧与求解方案）与播放器、
   结果表共用同一个 `session.plan`；导入后自动重新求解。

## 测试

```bash
npm test          # 17 个单元/对拍测试（含 1300+ 随机对拍）
npm run smoke     # 页面脚本端到端冒烟
```

对拍策略：在更小瓦片数（1×1、1×2、1×3、2×2）与更少帧数（≤10）下，
枚举全部 2^N 个动作序列、逐一模拟合法性与费用，比较与 DP 完全相同的
`(总费用, 全刷次数, 动作序列)`。迟到测试用 `vm` 加载与浏览器完全相同的
`buildWorkerSource()` 输出：先发起请求 A 不投递结果、再发起 B，验证
A 以 `SUPERSEDED` 拒绝、A 的迟到响应被静默丢弃、B 正常 resolve。
